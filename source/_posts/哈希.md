通常情况下 `STL` 的 `map` 可香了，但是一个缺点就是常数有些大。

因此手写哈希依然必要。

最首先的思路就是将 _要哈希的值_ 对 _一个质数_ 取模。对一个质数取模的好处是可以降低冲突的次数。（感觉的，没有证）

但是冲突终于还是会有的，所以对于冲突，有下面两种方法。

# 开放寻址法

```cpp
#include <cstring>
#include <iostream>
using namespace std;
const int N = 100010, null = 0x3f3f3f3f;
int h[200003];

int find(int x)
{
    int t = (x % N + N) % N;
    while (h[t] != null && h[t] != x)
    {
        t ++ ;
        if (t == N) t = 0;
    }
    return t;
}
```

函数 `find(x)` 表示的是，如果一个数 `x` 还没有被记录过，就返回它该存在什么地方，否则返回它在什么地方。
开放寻址法的思路是，如果如果发现当前下标位置被占了，就往后面寻找没有被占的地方，把数存进去。如果找到数组末尾了都没有，就循环到起点开始。

为了保证复杂度不爆炸，通常情况下数组大小应该开到题目数字数的两到三倍。

# 拉链法

```cpp
#include <cstring>
#include <iostream>

using namespace std;

const int N = 100003;

int h[N], e[N], ne[N], idx;

void insert(int x)
{
    int k = (x % N + N) % N;
    e[idx] = x;
    ne[idx] = h[k];
    h[k] = idx ++ ;
}

bool find(int x)
{
    int k = (x % N + N) % N;
    for (int i = h[k]; i != -1; i = ne[i])
        if (e[i] == x)
            return true;

    return false;
}
```

拉链法选择“在一棵树上吊死”。不是冲突吗？我直接在冲突的地方上一条链，插入的时候就往链上插，查询就在链上找。
